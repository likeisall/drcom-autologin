# 校园网自动登录（Dr.COM ePortal）

> Windows 上的校园网自动登录 / 保活脚本。开机后自动在后台运行，掉线自动重登，
> 状态变化时弹一条**带颜色的** Windows 通知。纯 PowerShell，**不依赖任何第三方模块**。
>
> **多账号**：账号密码写在同一张表里，主账号欠费停机 / 密码错时自动改用备选账号。

每次开机、每次掉线都要手动打开认证网页输账号密码 —— 这个脚本就是为了干掉这件事。

---

## 一、适用范围与已知限制（请先读这段）

**能用的前提**：你的学校用的是 **Dr.COM（城市热点）ePortal** 认证系统，
且门户的 `login_method = 1`（走 `/eportal/portal/login` 这个 JSONP 接口）。

本脚本在**作者本校天津科技大学**的部署上实测可用。Dr.COM 的部署差异不小，换一所学校可能需要调整，
**不能保证开箱即用**。判断你的门户是不是这一套、以及怎么改，见第七节。

**本脚本不做的事**：
- 不破解、不绕过认证 —— 它就是用你自己的账号密码，走门户自己的登录接口
- 不抓包、不联网上传任何数据 —— 所有请求只发往你自己填的校园网门户地址
- 不支持 `en_md5 = 1`（密码需 MD5）的门户，代码里留了常量但未接线，见第七节

## 二、三步搞定

| 顺序 | 双击这个 | 做什么 |
|:---:|---|---|
| 1 | `1-填写账号和密码.bat` | 弹出记事本，**账号和密码都写在里面**、保存 |
| 2 | `2-测试登录.bat` | 立即检测一次，看能否自动登录成功 |
| 3 | `3-安装开机自启.bat` | 以后开机自动在后台运行，掉线自动重登 |

> ⚠️ 但**在做这三步之前**，你必须先编辑 `campus-login.ps1` 顶部的「配置区」，
> 填上你的 **认证门户地址 `$PortalHost`**（见第四节）。学号密码则写在账号表里。

想取消就双击 `9-卸载自启.bat`。

### 想加一个备选账号？（可选）

**在同一张账号表 `accounts.txt` 里再加一行就行**，不用改脚本：

```
20230001|校园网|主账号的密码|主账号
20230002|中国联通|备选账号的密码|备选账号
```

第 1 行是主账号，后面都是备选。主账号被服务端**硬拒绝**
（欠费停机 / 密码错误 / 账号被锁 / 时长耗尽……）时，脚本会自动改用下一行的账号上网，
并弹一条蓝色的「已切换账号上网」通知。只想用一个账号？只写一行即可。

## 四、配置（第一次使用必改）

打开 `campus-login.ps1`，顶部「配置区」里只有这么几项：

```powershell
$AccountFileName = 'accounts.txt'   # 账号密码表文件名，一般不用改

$WlanUserIp  = ''         # 本机地址：留空 = 自动探测（推荐）
$WlanUserMac = ''         # 本机 MAC：留空 = 自动取（推荐）

$PortalHost = ''          # ★必填★ 认证门户地址（IP 或域名，不带 http:// 和端口）
$PortalPort = 801         # 门户端口，Dr.COM 通常是 801
```

**`$PortalHost` 怎么找**：未登录校园网时，用浏览器打开**任意 http 网站**
（比如 `http://neverssl.com`），会被自动跳转到认证页 —— **地址栏里那个 IP / 域名就是**。

### 账号与密码：都在 `accounts.txt` 里

双击 `1-填写账号和密码.bat` 编辑它；一行一个账号，按优先级从上到下：

```
学号|运营商|密码|名字
```

实际内容长这样（两个账号的运营商可以不一样）：

```
20230001|校园网|主账号的密码|主账号
20230002|中国联通|备选账号的密码|备选账号
```

| 字段 | 说明 |
|---|---|
| 学号 | 学号 / 工号，**不含**运营商后缀（写了 `@` 就原样使用、不再拼后缀） |
| 运营商 | 与门户页面选项逐字一致，见下表。**每个账号各填各的** |
| 密码 | 这个账号的密码 |
| 名字 | **可省略**。通知里显示的名字；省略时显示「账号1」「账号2」 |

其它规矩：

- 以 `#` 开头的是**注释行**，空行忽略
- 第 1 行是主账号，后面都是备选账号；**只想用一个账号就只写一行**
- 格式写错的行（字段不足、没写学号）会被**跳过并在日志里点名第几行**，不会让整个脚本罢工
- ⚠️ **密码里不能含 `|` 这个竖线**（它是分隔符）
- ✅ **改完保存即刻生效** —— 守护进程每次要重登前都会重读这张表，
  改密码 / 加账号 / 换运营商都不用重启电脑
- ⚠️⚠️ 本文件含**明文密码**，`.gitignore` 已把 `accounts.txt` 排除，
  **千万别 `git add -f` 它**

### 运营商与后缀

| 页面选项 | 实际后缀 | 脚本里也可以写 |
|---|---|---|
| **校园网** | （无） | `校园网` / `campus` |
| **中国联通** | `@unicom` | `中国联通` / `联通` / `unicom` |
| **中国移动** | `@cmcc` | `中国移动` / `移动` / `cmcc` |
| **中国电信** | `@telecom` | `中国电信` / `电信` / `telecom` |

最终提交的账号 = `$Account` + 后缀，例如 `20230001@unicom`。
> 若 `$Account` 里你自己写了 `@`，脚本就不再拼后缀。

## 五、运行模式

```powershell
.\campus-login.ps1 -Once      # 只检测/登录一次，然后退出（测试用）
.\campus-login.ps1            # 常驻守护：每 60 秒检测一次，掉线自动重登
.\campus-login.ps1 -Force     # 跳过在线检测，强制提交一次登录
.\campus-login.ps1 -Diagnose  # 只探测连通性，不登录（零副作用，排查用）
.\campus-login.ps1 -DryRun    # 只打印将要发出的请求（密码遮为 ***），不提交
```

常驻模式的间隔可以调：

```powershell
.\campus-login.ps1 -IntervalSeconds 30
```

### 会弹通知吗？

**会 —— 但只在「状态真的变了」的时候弹**。四种通知、四档颜色：

| 颜色（左侧大徽章） | 时机 | 通知标题 | 通知正文 |
|:---:|---|---|---|
| 🟢 绿✓ | 掉线后自动登录成功 | 校园网 · 已自动登录 | 账号 / 状态 / 时间 |
| 🔵 蓝✓ | 被拒后换号并成功 | 校园网 · 已切换账号上网 | 原账号 / 失败原因 / 改用账号 / 生效范围 / 时间 |
| 🟡 黄! | **主账号被拒**（单独提醒） | 校园网 · 主账号登录失败 | 账号 / 失败原因 / 后续动作 / 时间 |
| 🔴 红✗ | 所有账号都登不上 | 校园网 · 所有账号都登不上 | 逐个账号列出失败原因 / 处理建议 / 时间 |

> **账号表里只有主账号时**（没配备选）：不会弹黄色的「主账号登录失败」，
> 而是**直接弹红色的「所有账号都登不上」** —— 只有一个账号时，红色那条本来就把
> 主账号的失败原因列全了，再来一条黄的纯属啰嗦。

四条通知长这样（实际文案；`[绿]`/`[蓝]`/`[黄]`/`[红]` 只是本文档的标注，
**通知标题里不写圆点**，颜色由左侧大徽章表示）：

```
[绿✓] 校园网 · 已自动登录
  账号：主账号（20230001 / 校园网）
  状态：网络已恢复，掉线后会自动重登
  时间：2026-01-01 00:30:12

[蓝✓] 校园网 · 已切换账号上网
  原账号：主账号（20230001 / 校园网）
  失败原因：您的账号已停机
  改用账号：备选账号（20230002@unicom / 中国联通）
  生效范围：本次开机期间一直使用该账号
  时间：2026-01-01 00:30:12

[黄!] 校园网 · 主账号登录失败
  账号：主账号（20230001 / 校园网）
  失败原因：您的账号已停机
  后续动作：改用下一个账号「备选账号」
  时间：2026-01-01 00:30:12

[红✗] 校园网 · 所有账号都登不上
  已尝试 2 个账号：
  · 主账号（20230001 / 校园网） —— 您的账号已停机
  · 备选账号（20230002@unicom / 中国联通） —— 密码错误
  建议：给主账号充值后重启电脑即可自动切回；或双击「1-填写账号和密码.bat」核对 accounts.txt
  时间：2026-01-01 00:30:12
```

### 颜色是怎么上的

⚠️ **Windows 的 Toast 没有「整条通知变绿/变黄/变红」的接口** —— 卡片底色由系统主题决定，
应用无权改。能上色的只有**卡片左侧那张大图**，本脚本就靠它：
`icons\` 下的四张 64×64 透明 PNG，走 `appLogoOverride` + `hint-crop="circle"`。

- 图标文件丢了才退回标题圆点垫一下，否则整条通知一点颜色都没有
- 左上角那个「Windows PowerShell」小图标**改不了** —— 它来自发通知的应用身份
  （本脚本借用的是 PowerShell 自己的 AppUserModelID）

- ✅ **手动测试也弹**：双击 `2-测试登录.bat`（`-Once` / `-Force`）同样会弹，
  方便你验证通知本身。不过只有**真发生登录**才弹 —— 控制台报「网络在线，无需登录」时依旧安静
- `-Diagnose` / `-DryRun` 不涉及登录，**始终不弹**
- 只在下线 → 上线的**变化**时刻弹；联网正常时每 60 秒的探测是静默的，不会刷屏
- **不在校园网时不会弹**：门户连不上就判定为「不在校园网」，
  既不尝试登录也不通知 —— 在家、或刚开机 Wi-Fi 还没连上时都是安静的
- **同一段离线期内失败只弹一条**：否则每 60 秒一条会把人烦死；联网恢复后才允许再报
- 想收到横幅，需在「设置 → 系统 → 通知」里允许 **Windows PowerShell** 发通知；
  开了专注助手时可能只进通知中心、不弹横幅

## 六、工作原理

### 1. 判断是否在线

请求 `http://connect.rom.miui.com/generate_204`（失败则再试 `www.baidu.com`）：

| 现象 | 判定 |
|---|---|
| 返回 `204` | 在线 |
| 被 `302` 重定向到门户地址 | 未认证 |
| 返回 `200` 但内容含 `Dr.COM` / `eportal` | 被 HTTP 劫持，未认证 |
| 超时 / DNS 失败 | 按未认证处理 |

用两个目标是为了防止单一站点抽风导致误判、进而误触发重登。

### 2. 区分「不在校园网」和「登录被拒」

探测失败后**先看门户 TCP 端口通不通**（只做一次连接，不发认证请求）：

- **不通** → 判定为「不在校园网」（人在校外，或刚开机 Wi-Fi 还没连上）
  → 不尝试登录、不弹通知，安静等下一轮
- **通** → 才去提交登录；被拒才算真失败，弹一次通知

没有这一步的话，人在家里会被每 60 秒弹一条「登录失败」。

### 3. 提交登录（JSONP GET）

```
GET http://<你的门户>:801/eportal/portal/login
    ?callback=jsonpReturn
    &login_method=1
    &user_account=<账号+运营商后缀>
    &user_password=<明文密码>
    &wlan_user_ip=<本机在校园网的地址，自动探测>
    &wlan_user_ipv6=
    &wlan_user_mac=<上面那个地址所属网卡的 MAC，自动取>
    &wlan_ac_ip=&wlan_ac_name=
    &jsVersion=4.1.3
    &terminal_type=1&lang=zh-cn
    &v=<随机数，防缓存>
```

> ⚠️ **本项目的核心踩坑点**：参数名是 **`user_account` / `user_password`**，
> 而**不是**老接口的 `DDDDD` / `upass`。
> 把老参数名发到这个接口上，服务端会回
> `{"result":0,"msg":"无法获取用户认证账号！"}` —— 而 `DDDDD` / `upass`
> 其实属于 ruckus / 表单那条支路，跟这个 JSONP 接口不是一回事。
> 作者当初就是在这上面栽了跟头，所以特别标出来。

**本机地址是怎么定的**：把本机每个候选 IPv4 依次绑定为源地址、去连门户端口，
第一个连得通的即 `wlan_user_ip`，MAC 随之自动取。
这比「挑名字像 WLAN 的网卡」可靠 —— 多网卡、挂 TUN 模式代理时尤其明显。
所以**换了 IP、换了网卡、重启后 DHCP 重新分配，脚本都不需要改**。

### 4. 判断结果与等待放行

服务器返回 JSONP：

```javascript
jsonpReturn({"result":1,"msg":"...","ret_code":""})
```

- `result == 1` 或 `result == 'ok'` → 成功
- 其他 → 失败，`msg` 就是原因

**接口报成功 ≠ 立刻能上网**。AC 还要向 RADIUS 要授权再放行流量，有几秒延迟。
所以脚本会**轮询最多 45 秒**（每 5 秒一次）确认真的通了；仍不通就**整体重试登录**（最多 3 轮）。

### 5. 被拒就换号

`result` 不为 1/ok 时，把服务端 `msg` 拿去比对 `$HardFailurePatterns`：

- **命中** → 判为「这个账号本身废了」→ 跳出重试循环，直接用账号表里的下一个账号登录；
  换号成功就弹蓝色的「已切换账号上网」，并把生效账号记在内存里
- **没命中** → 判为临时故障 → 按 `$LoginRetryCount` 重试同一个账号；
  所有轮次都失败后才轮到下一个账号

关键词清单（`$HardFailurePatterns`）：

```
停机 欠费 余额不足 缴费 已过期 过期 到期 时长耗尽 时长已用完 时长不足
流量耗尽 流量已用完 流量不足 密码错误 密码不正确 密码有误 认证失败
账号不存在 用户不存在 未注册 未开通 已锁定 被锁定 已停用 已禁用 已销户
```

> 刻意**不含**「已经在线」—— 那说的是本机地址，不是账号问题。
> 命中关键词只是「换个账号试试」，脚本不会注销任何东西。
> 嫌误判就删掉几个关键词；想更激进就再加。

「当前账号」只存在进程内存里（`$script:ActiveAccountIndex`），**不落盘** ——
这正是「重启后重新从主账号开始」的实现方式：**换号后本机重启前不再回头撞主账号，
充完值重启一次就自动切回**。

换号全过程的 HTTP 请求序列（本地假门户实测，账号 1 停机、账号 2 可用）：

```
PROBE  online=False            <- 探测到掉线
LOGIN  11111111@unicom  n=1 -> result=0 msg=该账号已停机    <- 硬拒绝，只试这一次
LOGIN  22222222@unicom  n=1 -> result=1                     <- 换号，成功
PROBE  online=True             <- AC 放行，复验通过
```

### 6. 账号表热重载

守护进程**每次要重登前**都会重读 `accounts.txt`（只在掉线要登录这条路径上读，
每分钟的常规探测不受影响）。所以改密码 / 加账号 / 换运营商**保存即生效**，
不必重启电脑或守护进程。

那次没读出任何账号（正好在保存中）则沿用上一次的表并记一条 WARN。

## 七、适配你自己的学校

先确认是不是同一套。用浏览器打开这个只读接口（**不碰认证，安全**）：

```
http://<你的门户>:801/eportal/portal/page/loadConfig?program_index=&wlan_vlan_id=0
```

会返回一大坨 JSON，重点看四个字段：

| 字段 | 含义 | 本脚本的假设 |
|---|---|---|
| `login_method` | 认证方式 | 需要 **`1`**（走 `login_portal()` → JSONP 接口） |
| `en_md5` | 密码是否 MD5 | 需要 **`0`**（明文提交） |
| `account_prefix` | 账号是否要加前缀 | `0` = 不加；`1` = 需要 `,0,` 前缀（本脚本暂时只支持 0） |
| `enable_new_drcom_srv` | 新旧服务 | 与本脚本无关，仅供参考 |

**对不上的话**：
- `login_method` 不是 1 → 脚本针对的接口不同，需要照着门户前端源码改 `New-LoginFields`
- `en_md5` 是 1 → 密码要改成 `MD5(PID + 密码 + CALG) + CALG + PID`
  （脚本里已留 `$Md5Pid` / `$Md5Calg` 常量，但尚未接线）
- `account_prefix` 是 1 → 账号前面要加 `,0,`

怎么知道该发什么参数？**看门户自己的前端 JS**：未登录时打开认证页，
用浏览器开发者工具抓 `.js` 文件，搜 `login_portal` / `portal_login`，
那里面的 `data` 对象就是要照抄的参数表。本脚本就是这么做出来的。

## 八、常见问题

**Q：日志里说「还没配置好」**
`$PortalHost` 没填。见第四节。

**Q：日志里说「密码是空的。请打开 accounts.txt，把第 N 行的密码补上」**
双击 `1-填写账号和密码.bat`，把那一行的密码补上即可（日志会告诉你第几行）。

**Q：日志里说「登录失败：result=0 msg=xxx」**
`msg` 就是服务端给的原因。常见：

| msg 关键字 | 含义 | 处理 |
|---|---|---|
| 无法获取用户认证账号 | 服务端压根没收到账号参数 | 先跑 `-DryRun` 看请求串：参数名必须是 `user_account`，且 `wlan_user_ip` 要是本机校园网地址 |
| 密码错误 / 认证失败 | 密码不对 | 打开 `accounts.txt` 改那一行的密码 |
| 该账号已停机 | 套餐到期 | 去充值；**若表里还有下一行账号，脚本会立刻自动换号** |
| 账号已在线 | 别处已登录 | 注销其它设备 |
| IP 已经在线 | 本机已有会话 | 一般无害，脚本会复检外网，真通了就算已登录 |

**Q：主账号欠费停机了，会自动换另一个账号吗？**
会 —— 前提是 `accounts.txt` 里写了第二行账号（学号、运营商、密码都齐全）。
之后主账号一被硬拒绝就自动换号，并弹一条蓝色的「校园网 · 已切换账号上网」。

**Q：切到备选账号后，主账号充值好了怎么切回去？**
**重启一次电脑即可**（关机再开机也行）。换号状态只存在内存里，
开机自启的守护进程一重启就从主账号重新开始 —— 主账号能用就用主账号，
还是不能用就再自动切回备选。

**Q：怎么知道现在用的是哪个账号？**
三种办法：① 看通知；② 看 `campus-login.log` 里
「登录成功并已放行，当前使用『×××』」这一行；③ 直接跑
`.\campus-login.ps1 -Diagnose`，抬头会把账号表和优先级打出来。

**Q：我只想用一个账号，能不能不配备选？**
能。`accounts.txt` 里只写一行即可。此时主账号登不上会**直接弹红色**
「所有账号都登不上」（不会再有黄色那条），启动横幅也会提醒你「只有 1 个账号」。

**Q：不小心把 accounts.txt 删了 / 格式写坏了怎么办？**
删了：双击 `1-填写账号和密码.bat`，它检测到文件不在会**自动按模板重建**。
写坏了：格式不对的行会被**跳过并在日志里点名第几行**，其余行照常工作，
不会让整个脚本罢工。

**Q：接口报成功，但 45 秒后仍未放行**
脚本会写进日志。可能是账号被别的设备占用、或套餐时长耗尽。

**Q：刚登录成功又被踢**
该账号可能限制同时在线设备数；或者机器上的代理 / VPN 软件抢了流量。

**Q：每次开机先弹一条失败、再弹一条成功？**
不应该发生 —— 脚本会先判断门户可达性。若真出现，说明你的门户即使未认证也能连上端口，
把 `-Diagnose` 的输出发出来看看。

**Q：装好了但每次还是要手动登录**
先看 `campus-login.log` 有没有记录。没有记录说明守护进程没起来 ——
在任务管理器「详细信息」里找 `pwsh.exe`，看命令行是否包含 `campus-login.ps1`。

**Q：会不会影响网速 / 耗流量**
每 60 秒一次 `generate_204`，请求体极小（几百字节），可忽略。

**Q：怎么彻底卸载**
双击 `9-卸载自启.bat`，然后删掉整个文件夹。

## 十、技术备注

### 运行环境

- Windows 11 + PowerShell 7（也在 Windows PowerShell 5.1 下验证过语法）
- 自启方式：启动文件夹里的快捷方式（`install.ps1` 用
  `[Environment]::GetFolderPath('Startup')` 取路径，**不写死**）
  - 不需要管理员权限，不动注册表 `Run` 项
  - 在「任务管理器 → 启动应用」里可以看到 `CampusNet-AutoLogin`
  - ⚠️ 该路径**可能被系统重定向**（有些工具会搬走启动文件夹）。
    查自启是否装好，要看 `GetFolderPath('Startup')` 的实际返回值，
    而不是想当然去看 `%APPDATA%\...\Startup` —— 后者里的东西根本不会开机启动

### 编码要求（改文件前必读）

- `campus-login.ps1` / `install.ps1` / `notify.ps1` 都带 **UTF-8 BOM**，**不要去掉**
- 原因：`start-hidden.vbs` 找不到 pwsh 时会回退到 Windows PowerShell 5.1，
  而 **5.1 读「无 BOM 的 .ps1」会按系统 ANSI 解码**，中文乱码 → 语法错误
  （实测报 `UnexpectedToken`）。带 BOM 后 5.1 与 7 都能正确解析
- ⚠️ **这个坑很阴**：丢了 BOM 之后 **PowerShell 7 照常能跑**，
  `-DryRun` / `-Once` 都正常，**只有 5.1 报错** —— 也就是说日常测试根本发现不了，
  只在开机自启回退到 5.1 时才炸。**改完务必确认 BOM 还在**：
  ```powershell
  $b=[IO.File]::ReadAllBytes('.\campus-login.ps1'); $b[0] -eq 0xEF -and $b[1] -eq 0xBB -and $b[2] -eq 0xBF
  ```
- `.bat` 是 GBK（配合 `chcp 936`）、`.vbs` 是纯 ASCII —— 这两个**不要**加 BOM
- `notify.ps1` 里的彩色圆点用 `[char]::ConvertFromUtf32` **按码点构造**，
  源码里不出现 emoji —— 免得 5.1 读文件时出幺蛾子

### 通知图标（icons\）

四张 64×64 透明 PNG 由 `System.Drawing` 画出（绿底白✓ / 蓝底白✓ / 黄底白! / 红底白✗）。
想换样式，重新生成同名文件即可，`notify.ps1` 只按 `-Accent` 取 `icons\<色>.png`。
`ToastGeneric` 的图片必须走 `appLogoOverride` 这一处才能上色（`file:///` 本地路径实测可用）。

### 通知为什么非要走 5.1

PowerShell 7 加载不了 WinRT 类型，实测报：

```
找不到类型 [Windows.UI.Notifications.ToastNotificationManager,
            Windows.UI.Notifications, ContentType=WindowsRuntime]
```

所以 `notify.ps1` 由 `powershell.exe`（5.1）执行。
好处是**无需安装 BurntToast 之类的第三方模块**。

### v2.1 —— 修正登录参数名（**本项目最有价值的一次修正**）

v2.0 找对了接口地址，却把老接口的 `DDDDD` / `upass` 发到了新接口上，
服务端回 `result=0 msg=无法获取用户认证账号！`。

依据是门户 `a40.js` 里 `login.login_portal()` 的原文：

```javascript
login.login_portal = function (success, fail) {
    var data = {
        'login_method'  : page.login_method,
        'user_account'  : this.prefixAccount,     // ← 不是 DDDDD
        'user_password' : this.form.upass.value,  // ← 不是 upass
        'wlan_user_ip'  : term.ip,
        'wlan_user_ipv6': term.ipv6,
        'wlan_user_mac' : term.mac,
        'wlan_ac_ip'    : term.wlanacip,
        'wlan_ac_name'  : term.wlanacname,
        'jsVersion'     : jsVersion
    };
    login.portal_login(data, success, fail);   // 再补 terminal_type / lang
};
```

**A/B 对照实测**（用不存在的假账号，不碰真账号）：

| 参数名 | 服务端回应 |
|---|---|
| `user_account` / `user_password` | `IP: 10.x.x.x 已经在线！`（`ret_code=2`）→ 账号参数已被正确解析 |
| `DDDDD` / `upass` | `无法获取用户认证账号！` |

同一版还加了**本机地址自动探测**（绑定源地址试连门户，连通者即 `wlan_user_ip`，MAC 随之自动取），
以及 `-DryRun` 预演开关。

### v2.0 —— 修正登录接口

v1.x 用的是 `POST http://<门户>/eportal/?c=ACSetting&a=Login`（80 端口老接口）。
